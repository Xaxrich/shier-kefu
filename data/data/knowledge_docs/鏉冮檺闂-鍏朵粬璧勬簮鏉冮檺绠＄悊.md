# 其他资源权限管理指南

## 适用范围

本文档适用于员工在访问共享文件夹、代码仓库、NAS 存储、云服务等资源时遇到的权限问题。

---

## 共享文件夹权限

### 无法访问共享文件夹
1. 确认共享路径格式正确：`\\服务器名\共享名` 或 `\\IP地址\共享名`
2. 在文件资源管理器地址栏直接输入路径并回车
3. 如提示"没有权限"：
   - 确认你是否属于该共享文件夹的授权组
   - 联系文件夹的负责人或 IT 申请权限

### 申请共享文件夹权限
1. OA → IT 服务 → 文件夹权限申请
2. 填写：共享文件夹路径、需要的权限级别（只读/读写）、申请原因
3. 审批：文件夹负责人 → IT 执行
4. 处理时间：1 个工作日

### 权限级别说明
| 权限级别 | 可执行操作 |
|---------|-----------|
| 只读 | 查看、复制文件 |
| 读写 | 查看、复制、新建、修改文件 |
| 完全控制 | 以上全部 + 删除、修改权限（仅管理员） |

## 代码仓库权限（GitLab / GitHub）

### GitLab 无法访问项目
1. 确认是否已有 GitLab 账号（使用 OA 邮箱登录）
2. 新员工首次登录：访问 `gitlab.company.com` → 使用 OA 账号登录 → 自动创建账号
3. 项目权限由项目管理员分配：
   - 联系项目 Owner 或 Maintainer 添加你为成员
   - 或者 OA → IT 服务 → 代码仓库权限申请

### 权限角色说明
| 角色 | 权限 |
|------|------|
| Guest | 查看 Issue |
| Reporter | 查看代码、下载 |
| Developer | 提交代码、创建分支、MR |
| Maintainer | 合并 MR、管理成员、项目设置 |
| Owner | 完全控制，包括删除项目 |

### SSH Key 配置
如果 Git 推拉代码提示权限错误：
1. 检查是否已配置 SSH Key：终端执行 `cat ~/.ssh/id_rsa.pub`
2. 如果没有，生成新的：`ssh-keygen -t rsa -b 4096 -C "your@email.com"`
3. 复制公钥内容 → GitLab → 设置 → SSH Keys → 粘贴添加
4. 测试连接：`ssh -T git@gitlab.company.com`

## NAS 网络存储

### NAS 访问方式
- Windows：文件资源管理器 → `\\nas.company.com\部门名`
- Mac：Finder → 前往 → 连接服务器 → `smb://nas.company.com/部门名`

### NAS 无法访问
1. 确认在公司网络环境下（办公室或 VPN）
2. 确认账号密码正确（与 OA 相同）
3. 清理 Windows 凭据：控制面板 → 凭据管理器 → 删除 NAS 相关凭据 → 重新访问
4. 提交工单申请 NAS 权限

### NAS 空间申请
- 部门共享空间不足时，由部门主管提交扩容申请
- OA → IT 服务 → 存储空间申请

## 云服务权限

### 公司网盘
- 使用公司指定的网盘服务存储和分享文件
- 新员工默认开通基础空间（50GB）
- 扩容申请：OA → IT 服务 → 网盘空间申请

### 其他云服务（AWS / 阿里云等）
- 由 IT 或运维统一管理
- 需要访问权限：OA → IT 服务 → 云服务权限申请
- 需提供：服务名称、所需权限、使用场景
- 审批：部门主管 → IT 安全 → 运维开通

---

## SVN 仓库权限

### SVN 无法检出代码
1. 确认 SVN 客户端已安装（推荐 TortoiseSVN）
2. 确认仓库地址正确
3. 使用 OA 账号登录
4. 权限不足：联系项目管理员或提交 OA 工单

---

## 数据库访问权限

### 申请流程
1. OA → IT 服务 → 数据库权限申请
2. 填写：数据库名称、需要的权限（只读/读写）、访问目的
3. 审批：部门主管 → DBA → IT 安全
4. 注意：生产环境数据库默认只授予只读权限

## 常见问题

**Q：权限申请一般多久能审批？**
A：普通权限 1-2 个工作日，涉及安全评估的 3-5 个工作日。

**Q：离职 / 转岗后权限会自动回收吗？**
A：是的，HR 发起离职/转岗流程后，IT 会自动回收相关权限。

**Q：可以把自己的权限分享给同事吗？**
A：不可以。严禁共享账号或借用他人权限，每人须独立申请。
